The path to the app store

الطريق إلى متجر التطبيقات

These five steps are strictly ordered — each one is impossible until the one before it is done. Supplying the Firebase key first, for example, changes nothing anyone can see.

هذه الخطوات الخمس مرتّبة بشكل صارم — كل خطوة متعذّرة قبل إتمام ما قبلها. فتوفير مفتاح Firebase أولًا، مثلًا، لا يُحدث أي أثر ملحوظ.

  1. Create the app signing certificate. 15 minutes. Google Play rejects every build produced so far. Release builds now fail rather than producing an unpublishable file.
  2. إنشاء شهادة توقيع التطبيق. 15 دقيقة. يرفض Google Play كل النسخ المُنتَجة حتى الآن. بناء نسخة الإصدار يفشل الآن بدل إنتاج ملف غير صالح للنشر.
  3. Build a new APK. 1 hour, ours. Every current install predates the notification code, so no phone can ever register.
  4. بناء نسخة APK جديدة. ساعة، من جهتنا. كل النسخ المثبّتة حاليًا سابقة لكود الإشعارات، فلا يمكن لأي هاتف أن يُسجَّل.
  5. Supply google-services.json. 10 minutes. From Firebase → Project settings → General. The Android package must read exactly tech.saasfarm.ahlashabab; any other value fails silently, forever.
  6. توفير ملف google-services.json. 10 دقائق. من Firebase ← إعدادات المشروع ← عام. يجب أن يكون اسم الحزمة بالضبط tech.saasfarm.ahlashabab؛ أي قيمة أخرى تُفشل الإشعارات بصمت وإلى الأبد.
  7. Supply the Firebase service account key. 10 minutes. Added as a repository secret — it never passes through a person or a repository. A workflow installs it on the server and reports whether push came up.
  8. توفير مفتاح حساب خدمة Firebase. 10 دقائق. يُضاف كـ Secret في المستودع — فلا يمرّ عبر شخص ولا يُحفظ في أي مستودع. وهناك إجراء آلي يُثبّته على الخادم ويُبلّغ بنتيجة التفعيل.
  9. Send the first notification, and watch it arrive. The first end-to-end proof. Worth doing deliberately rather than discovering it in production.
  10. إرسال أول إشعار ومتابعة وصوله. أول إثبات كامل من طرف إلى طرف. يُنفَّذ بشكل متعمَّد بدل اكتشافه أثناء التشغيل.
